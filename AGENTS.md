# TFM Evaluator App - Project Memory

## Funcionalidades de gestión del proyecto (app)
- **Nuevo proyecto**: la plantilla se entrega VACÍA (0 escenarios). `reset_project()` restaura el estado recién creado: borra escenarios, elimina dominios personalizados (vuelve a los 14 base en `base_domains_es`) y borra `custom_capabilities.csv`. Botón "Reiniciar proyecto" (Acciones) con modal de confirmación (`btn_reset_project` → `btn_confirm_reset`).
- **Dominios nuevos**: `add_new_domain(domain_id, domain_name)` registra en domains.csv y crea la hoja en survey.xlsx (estructura estándar, 0 escenarios). ID: 2-10 caracteres alfanuméricos, único, no reservado. Formulario en Parámetros (`new_domain_id`, `new_domain_name`, `btn_add_domain`); `domain_refresh` reactiveVal refresca el selector.
- **Controles propios por NOMBRE**: en el módulo de capabilities hay DOS vías: (a) botón dedicado "Crear control propio" (`new_control_name` + `btn_create_control`) y (b) escribir un nombre nuevo en el selector (+ Enter) y pulsar "Añadir". Ambas generan ID interno `next_custom_id()` (CTRL-01, CTRL-02...) y persisten (id+nombre) en custom_capabilities.csv con feedback (showNotification; los errores de escritura NO se tragan en silencio). Además, `persist_unknown_controls()` registra automáticamente en custom_capabilities.csv los controles referenciados por escenarios que aún no existen (al añadir el escenario por formulario y al ejecutar el análisis), para no perder avance. IMPORTANTE: `persist_unknown_controls()` SEPARA por comas los strings de controles (la columna controls de qualitative_scenarios llega como "CTRL-01, CTRL-02"); sin esto se escribían filas corruptas con la lista completa como capability_id. Al SELECCIONAR un control existente en el selector, el módulo precarga costo/efectividad/descripción desde custom_capabilities.csv (observeEvent sobre capability_id) para que re-añadirlo tras limpiar el módulo no ponga costo 0. `upsert_custom_capability_params(conf)` persiste costo/efectividad de controles personalizados YA registrados (se llama al añadir un escenario con el módulo configurado y al pulsar "Añadir" sobre un control existente): sin esto, `persist_unknown_controls()` solo registraba controles NUEVOS y el costo configurado se perdía al limpiar el módulo (la optimización veía costos en 0 y ROSI global N/D). Respaldo: `dl_custom_capabilities` (descarga CSV) y `upload_custom_capabilities` (importa con upsert y refresca el selector vía `custom_caps_refresh`). El import ADVIERTE (toast warning) si el CSV no trae costos (columna `cost` ausente o vacía): la optimización los vería en 0 y el ROSI global saldría N/D. `merge_custom_capabilities()` fusiona los personalizados al catálogo en el análisis (default diff "3 - Definido/Defined") para que el pipeline los trate como primera clase (sin warnings). `capability_es_name()` cae al nombre personalizado para las tablas.
- **custom_capabilities.csv persiste costo y efectividad**: esquema `capability_id, capability, cost, eff_min, eff_mode, eff_max` (compatible con CSVs antiguos de solo id+nombre). `read_custom_capabilities()` rellena columnas ausentes y DESCARTÁ filas corruptas cuyo capability_id contenga comas (bug antiguo de persist_unknown_controls); `write_custom_capability()` guarda costo y Beta-PERT (descarta filas con ID ausente para no romper el rbind por lecturas parciales de OneDrive) y PRESERVA valores existentes cuando el nuevo es NA (un costo 0 explícito sí sobrescribe): protege los costos importados de un re-registro accidental con NA. `persist_unknown_controls()` también incluye los IDs del sidecar custom en su chequeo de "conocidos" (nunca re-registra controles que ya existen aunque el catálogo no los vea por OneDrive). El módulo persiste costo/efectividad al crear/añadir controles, y `persist_unknown_controls()` los copia del módulo al añadir un escenario. `control_costs_effective()` y `capability_pert_params_effective()` fusionan lo persistido en el CSV con lo configurado en el módulo (prioridad módulo) para análisis/mitigación/optimización, de modo que el ROSI usa el costo aunque el módulo se haya limpiado tras añadir el escenario. En optimización, si el costo total seleccionado es 0, `opt_message` avisa "controles con costo 0" (y ROSI global sale N/D porque es división por 0).

## App structure (Shiny app dir: `app/`)
- `app/global.R` - libraries + sources (fit_dist.R, evaluator_helpers.R, capabilities_module.R) + helpers (`build_dimension_value`, `vb_icon`, `fmt_compact_money` [K/M/B], `parse_params_string`, `dist_sample`, `dist_density_plot`, `no_scenarios_plot`, `no_scenarios_table`, `empty_plotly`, `dash_layout(legend_pos)`, `kpi_colors`, `kpi_card`) + `app_theme` (bslib darkly). Comentarios 100% en español.
- `app/ui.R` - modern bslib + Tailwind UI. Sidebar accordions (value ids: params/capabilities/actions), KPI cards via `kpi_card()`. ALL input/output IDs unchanged vs legacy app.R. Selectores TEF/TC/LM: etiquetas visibles en español, VALORES en inglés (los entiende evaluator: qualitative_mappings.csv).
- **Optimización de controles (mochila/ROSI)**: pestaña "Optimización de Controles" con `opt_mode` (per_scenario | global) + `opt_budget` + `btn_run_opt`. `knapsack_best_controls()` (enumeración exhaustiva 2^n, n<=24, maximiza ROSI con desempate por ahorro neto) y `optimize_controls_rosi()` (por escenario); `pareto_indices()` + `optimize_controls_global()` (MCKP con DP sobre costos alcanzables para presupuesto GLOBAL repartido entre todos los escenarios, maximiza ahorro neto total; devuelve list(by_scenario, totals)). Usa `control_level$marginal_savings` como beneficio y `control_costs` del módulo como costo (solo controles con costo). Requiere análisis + mitigación + costos configurados (tras añadir un escenario se limpia el módulo, hay que reconfigurar costos). Fundamentación matemática en `docs/fundamentacion_matematica.tex` (incluye sección MCKP).
- `app/server.R` - full reactive logic (simulation, mitigation, capabilities module, downloads). KPIs use `fmt_compact_money`; bar charts use `dash_layout(legend_pos = "top")`. Estados vacíos: cada módulo de gráficos (Monte Carlo, LEC, Sensibilidad, Mitigación) muestra `no_scenarios_plot()` / `no_scenarios_table()` con "Esperando ingreso de escenarios..." cuando hay 0 escenarios (chequeo ANTES de `req(input$...)` del selector). Al añadir un escenario por el formulario: mensaje con el ID + `showNotification` y `reset_scenario_form()` limpia descripción, TComm, TEF, TC, LM y los controles configurados (`caps_module$clear()`).
- `app/www/css/app.css` - compiled Tailwind + custom design CSS (dark-mode first via `[data-bs-theme="dark"]`).
- `app/evaluator_helpers.R` - workspace mgmt (`find_app_dir()` resuelve SIEMPRE a `app/evaluator_workspace` aunque la app se lance desde la raíz del proyecto; `load_survey_workbook()` da error claro si survey.xlsx es placeholder de OneDrive ilegible), survey write/import, `scenario_missing_capabilities()` (detecta controles referenciados por escenarios que NO existen en el catálogo y `run_evaluator_analysis` los devuelve en `missing_capabilities` para avisar en la UI). VALIDACIÓN de valores TEF/TC/LM ANTES de encode: si un escenario trae valores vacíos (NA) o no reconocidos (p. ej. "Frecuente"), `run_evaluator_analysis` detiene con mensaje claro nombrando el escenario y el campo; encode también está envuelto con error claro. Respaldo de controles en panel Acciones (`upload_custom_capabilities` + `dl_custom_capabilities`)., y helpers de históricos TEF/LM con selección de hoja/columna (`hist_file_sheets`, `hist_file_columns`, `hist_file_vector`)
- `app/global.R` - `options(shiny.maxRequestSize = 100MB)` para subir históricos grandes (`import_uploaded_survey_data` con UPSERT por ScenarioID: importar 2 veces no duplica; `is_sectioned_survey_file()`/`import_sectioned_survey_scenarios()` permiten subir el survey.xlsx SECCIONADO descargado por la app), `run_evaluator_analysis()` (returns results_dir, simulation_results, scenario_summary [tcomm/description], domain_summary, qual inputs; **short-circuit con 0 escenarios**: devuelve marcos vacíos con las columnas esperadas), `run_mitigation_analysis()` (inherent vs residual + leave-one-out + ROSI; **también short-circuit vacío**), `mc_convergence_check()`, `run_sensitivity_tornado()` (±20% TEF/TC/LM), `generate_executive_narrative()` (3-paragraph board summary), `check_ollama_status()` + `build_ollama_prompt()` + `generar_resumen_ia()` (IA local Ollama, env `ENABLE_OLLAMA`, mensaje amigable si inactivo), `build_chat_system_prompt()` + `preguntar_a_ollama()` (chat contextual `/api/chat` con historial, httr2, modelo llama3.2:1b), `get_evaluator_capabilities()` (reads inputs/capabilities.csv + custom_capabilities.csv sidecar + capabilities_es.csv para nombres en español), `capability_es_name()`, `capability_es_description()`, `top_controls_text()` (top-5 controles en español para prompts del Copilot), `reset_survey_template()` (deja SOLO encabezados).
- `app/fit_dist.R` - `fit_dist()` count/severity fits, BIC selection. Comentarios en español.
- `app/capabilities_module.R` - Shiny module to configure controls with Beta-PERT effectiveness (min/mode/max %) + cost ($) for ROSI. Client-side selectize `create = TRUE` lets users create NEW control IDs (persisted with description to `inputs/custom_capabilities.csv`). Returns `configured`, `capability_ids_csv()`, `capability_pert_params()`, `control_costs()` (named vector id->$). Integration: `run_evaluator_analysis(custom_diff_params = ...)` merges over `scenario$parameters$diff` via `utils::modifyList`.
- `evaluator/` - local fork. `parse_string()` maps dist names to r-prefixed RNG funcs (lnorm -> stats::rlnorm, pert -> mc2d::rpert...). **`sample_lm()` soporta cap de pérdida**: si `params` trae `max` y la RNG NO lo usa como parámetro nativo (pert/unif sí), se retira antes de llamar a la RNG y se aplica `pmin(samples, max)`. Así un LM `dist:lnorm|params:meanlog=...,sdlog=...,max=50000` limita la pérdida por evento para TODAS las distribuciones. NOTA: `params` llega como vector atómico nombrado (unlist en openfair_tef_tc_diff_lm) → usar `[[` no `$`. `select_loss_opportunities()` handles empty diff (inherent). **`split_sheet()` parcheado**: con 0 filas de escenarios devuelve marco vacío (antes generaba filas basura con el encabezado). Reinstall: `devtools::install("../evaluator", quick = TRUE, upgrade = FALSE)` (desde `app/`) y reiniciar sesión R si estaba cargado; en Docker SIEMPRE `docker compose build` tras tocar el fork.
- **Límite máximo de pérdida (LM)**: parámetro `max=<monto>` en el string de distribución del survey (ej. `dist:lnorm|params:meanlog=2.681,sdlog=3.128,max=50000`), aplicado por `sample_lm()` (fork) tras el muestreo (cap por EVENTO; el ALE suma eventos capeados). En la vista previa, `dist_sample()` (global.R) aplica el mismo cap (con `params[["max"]]`, lista o vector) y el dropdown LM ahora incluye gamma, lnorm, weibull, exp, norm, beta, unif, pert (helpText explica `max=`). Para pert/unif `max` es la cota nativa (no se toca).
- **Importar encuesta (survey_file)**: al seleccionar archivo, `showNotification` avisa y recuerda pulsar "Añadir escenario al survey.xlsx"; al importar, `showNotification` (toast) con el nº de filas además de `analysis_message` (que solo se veía en la pestaña Configuración).
- **Curva de excedencia (LEC)**: `exceedance_plot` filtra `is.finite(ale)` ANTES de la curva y de los cuantiles; si no quedan valores finitos muestra `empty_plotly("Sin valores finitos de pérdida...")` y los marcadores P10/P50/P90 se omiten cuando el cuantil no es finito (antes salía "P10: $NA" feo).

## Catálogo de controles 100% en español

## Survey format
- `app/evaluator_workspace/inputs/survey.xlsx` - **plantilla VACÍA**: solo encabezados + sección de capabilities de referencia, 0 filas de escenarios. `evaluator_workspace()` llama a `reset_survey_template()` tras `create_templates()` en deployments nuevos. `write_survey_scenario()` (V1-V7, append mode). Modes: Qualitative (label), Distribution/Fit (`dist:<name>|params:k=v,...`), PERT (`dist:pert|params:min=X,mode=Y,max=Z`). ## Multiproyecto (pestaña "Proyectos")
- Un proyecto = un evaluator_workspace propio (inputs/ + results/). La app trabaja sobre el proyecto activo vía `options(tfm.project_dir)`; si no hay override usa el clásico `app/evaluator_workspace`. `evaluator_workspace()` (evaluator_helpers.R) lee ese override; TODOS los helpers que llaman evaluator_workspace() cambian de proyecto automáticamente.
- `proyectos_root()` = app/proyectos (subcarpetas, una por proyecto; en Docker es el volumen ./app/proyectos). `proyectos_plantilla()` = app/proyectos_plantilla (plantilla LIMPIA en español: 0 escenarios, 14 dominios base, capabilities_es.csv, SIN capabilities.csv ni qualitative_scenarios.csv que son regenerables). Se generó copiando el workspace y aplicando reset_project(). OJO: `file.copy(recursive=TRUE)` necesita que el destino EXISTA (dir.create previo) o ignora recursive.
- `list_proyectos()`, `nuevo_proyecto(nombre)` (slug sin acentos, siembra desde plantilla), `set_proyecto_actual(path)`, `limpiar_proyecto_actual()`, `proyecto_actual_nombre()`.
- server.R: pestaña Proyectos (select + Abrir + Crear), `cambiar_proyecto()` limpia reactives (analysis/mitigation/opt/convergence/sensitivity), refresca domain_refresh/custom_caps_refresh, limpia caps_module y recarga caché del proyecto.

## Persistencia de resultados (no re-simular al abrir)
- Al final de run_evaluator_analysis() se llama `guardar_cache_analisis(res, iterations)`; tras una mitigación exitosa server guarda también `mitigacion`. Archivo: <results>/cache_analisis.rds.
- `analisis_firma()` = md5 de escenarios del survey + capabilities.csv + qualitative_mappings.csv + custom_capabilities.csv (incluye costos/eff) + domains.csv. Cualquier cambio invalida la caché.
- Al abrir la app (y al cambiar de proyecto), `cargar_cache_analisis()` devuelve el análisis (y mitigación) si la firma coincide → dashboard pinta sin Monte Carlo. El mensaje avisa "Resultados cargados de la sesión anterior".

## Optimización (costos en 0 / ROSI N/D)
- `control_costs_effective(module_costs)`: el módulo pisa el costo del CSV SOLO si configura >0 o el control no está en el CSV (un 0 del módulo por defecto NO borra el costo importado). Antes el 0 por defecto pisaba costos reales.
- btn_run_opt ahora emite diagnóstico visible: nº de costos detectados (CSV+módulo) con ejemplos, o "NO se detectaron costos (N controles en mitigación sin costo)". El mensaje final resume costo óptimo/ahorro neto/ROSI.

## Key gotchas
- **OneDrive Files-On-Demand**: bajo OneDrive, archivos del workspace pueden quedar "online-only" (`ls -laO` muestra `compressed,dataless`) y su lectura/escritura da "Operation timed out" → crash de la app. `get_evaluator_capabilities()` ya cae al sidecar español si capabilities.csv es ilegible; para regenerar placeholders de artefactos (capabilities.csv, qualitative_scenarios.csv) basta borrarlos y correr import_spreadsheet desde survey.xlsx. RECOMENDADO: sacar el proyecto de OneDrive o fijar "Keep on this device".
- **global.R no depende del CWD**: `app_dir` se resuelve buscando global.R+ui.R+server.R hacia arriba (y ./app); los source() usan rutas absolutas a app_dir. La app arranca desde la raíz o desde app/.
- **vroom en Docker**: readr 2.x necesita vroom para cargar. La imagen SIN vroom hace que la app reviente al conectar el navegador ("se desconectó el servidor") porque get_evaluator_domain_choices() llama readr::read_csv. Dockerfile instala readr+vroom explícitamente; SIEMPRE reconstruir la imagen tras cambiar paquetes: `docker compose build && docker compose up -d`. En run_evaluator_analysis se usa readr::cols (nunca vroom::cols).
- Simulator resolves `func` via `get(fn, asNamespace(pkg))` - must use r-prefixed RNG names.
- `openfair_tef_tc_diff_lm` sets `set.seed(31337)` (deterministic).
- Run app from `app/` directory (relative sources).
- bslib `accordion_panel` requires character title OR explicit `value=` (tag titles need `value=`).
- ISMP sheet has Excel table objects (`ISMP_Capabilities` A2:D5, `ISMP_Threats` A8:G9) - avoid rewriting header row with openxlsx (cell clears only). `getSheetNames()` recibe RUTA de archivo, NO objeto Workbook.
- `removeTable(wb, sheet, table)` en openxlsx 4.2.7.1 (no tiene keepHeader; elimina el objeto tabla conservando celdas).
- Con plantilla vacía: `run_evaluator_analysis`/`run_mitigation_analysis` hacen short-circuit ANTES de simulate/summarize (summarize_domains falla con 0 escenarios).
- Las rutas relativas a survey.xlsx pueden fallar intermitentemente bajo OneDrive; usar normalizePath() si loadWorkbook da "invalid 'file' argument".
- DT for tables; plotly >= 4.12 needed for ggplotly with ggplot2 >= 3.5.
